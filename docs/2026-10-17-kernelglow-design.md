# KernelGlow 设计文档

日期：2026-10-17。状态：设计定稿待实现。本文档是 KernelGlow 插件的唯一设计依据，实现计划（writing-plans 产物）从这里派生。

## 1. 背景与问题

UE 引擎卷积 Bloom（4.x Bloom→Convolution / 5.x BloomMethod=Convolution）的输入是**全屏亮度过阈像素**。kernel 调大后：每个过阈像素铺开成占屏比例的光晕、大面积亮部（天空/LED/自发光）把光晕罩满全屏；不做能量归一化时 kernel 总能量随面积膨胀，画面泛灰；结果又从低分辨率 buffer 上采样叠加。三者叠加表现为"kernel 调大 → 整个场景发糊"，且无法通过调参根治。

## 2. 目标与非目标

### 目标
1. **选择性 kernel 卷积辉光**：只有被标记的高光（来源白名单）参与卷积，kernel 半径任意大也不影响场景本体清晰度。
2. **独立性与持久化（硬性契约）**：
   - 独立性：插件渲染 pass 与引擎 Bloom 并列，引擎 Bloom（含卷积）完全关闭后插件效果完整存在；验收要求引擎 Bloom 开/关两种状态下插件输出逐像素一致。
   - 持久化：设置存项目配置（`UCLASS(config=Engine)`），启用后总开关默认开；重启编辑器 / 切关卡 / PIE / 打包均保持，无需每次手动开。一次性动作为安装时在项目里启用插件。
3. **视觉目标（鸣潮方向）**：清晰核心 + 彩色局部辉光 + 克制的大范围扩散；整体不发灰、黑位与对比度保持。鸣潮仅作公开画面的视觉规律参考，不声称复现其内部专有实现（沿用 CinematicGlow 的参考边界声明）。
4. **视觉品质条款（用户 2026-10-17 补充）**：
   - 柔和：光晕衰减连续，无可见色带与台阶。
   - 平滑：核心到边缘平滑过渡，上采样不产生块状痕迹。
   - 范围可控：光晕范围由用户实时调节（三层半径滑杆，0.01–1 屏幕占比）。
   - 提亮正确：该提亮的部分才提亮——只有过阈值/被标记的高光提亮，中间调与暗部不动。
   - 影响周围：高光以加性方式扩散到邻域（有溢出感），不遮挡、不压暗背景。
5. **形态**：UE 5.7 / Win64；编辑器面板 + 运行时（PIE / -game / 打包）都可用。

### 非目标
- 不修改引擎源码；不做 CinematicGlow 旧 Look/Profile/JSON 格式兼容；UE4.26 移植与移动端 / VR / MRQ 全量输出不在 v1 范围；不是物理镜头模拟（kernel 为艺术化 PSF）。v1 只保证主游戏视口与编辑器主视口；分屏多人不做；编辑器预览视口（材质/Niagara 预览）与捕获类视口默认跳过，视口应用策略在 M1 定稿。

## 3. 关键决策记录（已与用户确认）

| 决策点 | 结论 | 理由 |
|---|---|---|
| 技术路线 | 全新独立插件（不复用 CinematicGlow 基建） | 用户选择；需独立发布与解耦 |
| 目标引擎 | UE 5.7（Win64） | 用户选择；工作区有 TrueGlow-Host 5.7 冒烟宿主 |
| 卷积输入 | 选择性来源（非全屏 bright pass） | 根治糊场景 |
| 渲染技术 | Kernel 贴图卷积为主 + 固定小核核心回填 | 用户选择 kernel 为主；纯卷积出不了鸣潮式清晰核心，回填层是卷积体系内的锐度保险 |
| UI | WinUI 3（Fluent）单面板 4 卡片布局 | 用户指定 WinUI 3；7 页导航版被否（太繁琐） |
| 参考插件 | RealBloom（Fab, TOXIC STOCK） | 借骨架：ViewExtension + RDG GlobalShader + config 设置 + Slate 窗口；其全屏输入/纯高斯不解决本问题 |

## 4. 架构

- **模块 `KernelGlow`（Runtime，PostConfigInit）**：`FSceneViewExtension` 订阅后处理通道（`SubscribeToPostProcessingPass` / `PrePostProcessPass_RenderThread`），全部 pass 用 RDG GlobalShader（参考 RealBloom 的 UE5.6/5.7 接口用法）。SceneCapture 视图族默认跳过（防递归，fail-closed）。
- **模块 `KernelGlowEditor`（Editor，Default）**：Slate 工具窗口（编辑器 Window 菜单入口），实时调参。
- **设置**：`UKernelGlowSettings : UObject`，`config=Engine`；运行时开关另设 CVar。PIE 与打包行为一致。
- 落盘 `F:\Cache\AI\KernelGlow`，独立 git 仓库；冒烟宿主**新建隔离宿主 `F:\Cache\AI\KernelGlow-Host`（UE 5.7）**——不复用 TrueGlow-Host：其中含 TrueGlow/CinematicGlow 系插件的 ViewExtension，同场启用会与插件渲染 pass 冲突，且验收纪律要求隔离宿主。

## 5. 渲染管线

```
输入源合成(Stencil掩码 ∪ 外部RT ∪ 可选全屏亮源)
  → 软阈值提取(膝部过渡，f16 HDR)
  → 降采样金字塔(默认 5 级，随质量档收缩)
  → 多尺度 kernel 卷积 ×3(同 kernel 贴图，各尺度独立半径/强度/染色)
  → 核心回填(全分辨率固定小核锐层)
  → 上采样累加 → 加性合成回场景(HDR，Tonemap 前)
```

### 防糊的关键机制（与引擎卷积的本质差异）
1. **输入选择性**：卷积输入只含标记高光，场景本体不参与。
2. **kernel 预处理**：能量归一化（权重和恒为 1）+ 亮度钳制 + 中心偏移；kernel 建 mip 链。
3. **固定 Tap 预算**：每像素固定采样网格（默认 8×8=64 tap，从对应 mip 采样）。**kernel 半径只决定用哪级 mip，Tap 数与成本不变**——"调大"不会引发糊与成本的正反馈。

### 柔和/平滑的实现手段
- 软阈值膝部（smooth knee）避免光晕起点生硬；中间缓冲 f16 防色带；卷积权重和恒一保证能量连续；上采样双线性。
- 核心回填保证鸣潮式清晰核心不被卷积糊化。

## 6. 来源系统（v1 三种，可叠加）

1. **Custom Stencil 白名单**：Mesh 标 stencil 值入池（多值）。
2. **自定义 RT**：外部注入 RenderTarget（SceneCapture / 材质输出；为大屏联动预留）。尺寸/格式不合法 → fail-closed 跳过并日志警告。
3. **全屏软阈值亮源**（默认关）：需要引擎式全局溢出时开启。

所有来源关闭时插件无输出。第一版不做 Niagara 材质输出源（后续版本评估）。

### Kernel 贴图导入规格
- **必须 Linear（非 sRGB）**，灰度（形状）或彩色（带染色 kernel）；sRGB 导入会使能量归一化失真——插件导入时校验颜色空间并警告。
- 分辨率 ≤1024，强制生成 mip（半径→mip 映射依赖 mip 链）。
- 测试用 kernel 资产（圆盘/六边形/星芒程序化 + 至少一张实拍风格 PSF）随宿主交付。

### 测试关卡（交付物）
鸣潮式效果 = 发光体本身的 HDR 亮度设计 + 插件溢出，验收需要一套"发光体矩阵"测试关卡：小灯珠、中面板、大面积自发光屏、角色描边发光、未标记前景参照物，放宿主工程内随 M1/M2 搭建。

## 7. UI 设计（WinUI 3 单面板）

原型：`docs/ui-proto-kernelglow-panel.html`（本仓库内，可用浏览器直接打开）。布局为**单窗口单列 4 卡片**：

1. **首卡（常开）**：启用开关、总强度、亮度阈值、kernel 贴图槽 + 程序化回退形状（圆盘/六边形/星芒）。
2. **光晕形状（默认折叠，摘要"3 层 · 回填开"）**：尺度 1/2/3 各自半径/强度/染色 + 核心回填半径/强度。
3. **来源（默认折叠，摘要"Stencil n · RT n"）**：Stencil 白名单 chips、RT 槽、全屏亮源开关。
4. **高级（默认折叠，摘要"HDR · 8×8 · 档位"）**：合成时机、调试视图（遮罩/尺度隔离/前后对比）、质量档、Tap 预算、Fast 模式。

顶部 InfoBar 常驻说明独立性与持久化契约。视觉规范：Fluent 深浅主题跟随、强调色青蓝 `#0FA7E6`（可调）、卡片圆角 8px、Segoe UI Variable 字族。

**Slate 自绘控件清单（3 个）**：折叠卡片（Expander + 头部摘要）、ToggleSwitch（40×20 轨道）、SelectorBar（下划线/填充选中态）。其余用原生 Slate 控件换肤。窄宽度（编辑器停靠）适配为必验收项。

## 8. 性能预算

- 目标：2560×1440 / 高档 / RTX 4060 级 ≤ 1.5 ms（参照 CinematicGlow 4.26 实测多 pass 组合 ~1.4 ms）。
- 成本由 Tap 预算 × 金字塔级数 × 输入分辨率决定，**与 kernel 尺寸无关**；此声明本身列为验收项（半径 0.06 与 0.5 屏耗时差 < 5%）。
- Fast 模式：输入降采样，现场救急。

## 9. 验收

### 验收纪律（硬性规则，用户 2026-10-17 指定）
**UI 与效果都必须通过视觉验证。** 数值回归、自动化测试通过、三目标编译成功均不构成完成依据；任何"完成"声明必须附带对应的视觉证据（编辑器/PIE 截图或录屏，归档到宿主 `Saved/KernelGlowValidation/`，按日期+里程碑命名）。实现计划（writing-plans 产物）中每个里程碑的完成定义必须包含对应的视觉验收步骤；无法当场取得视觉证据的工作项，状态只能标为"数值通过，待视觉验收"。

### 数值/自动化
- 原生测试（TEST 框架）：kernel 能量归一化数学、mip 选择与半径映射、金字塔尺寸计算、来源快照、参数钳制、配置持久化读写。
- 编译验收：Editor / Development / Shipping 三目标。

### 视觉验收管线（需要视觉）
- **首选 unreal-mcp**：把 unreal-mcp 插件接入隔离宿主 KernelGlow-Host 5.7（`.uproject` 插件项 + 自动启动 ini，按其 references/setup.md），编辑器启动后会话内获得 `call_tool` 通道：布景、改参、控制台命令、截图回传，闭环在对话内完成。
- **兜底 HighResShot**：`-ExecCmds` 落盘到固定验证目录（沿用 `Saved/<Plugin>Validation` 归档习惯），读 PNG 评审。
- **图集规范**：同机位同参数成对截图（插件开/关；kernel 0.06 vs 0.5 屏；阈值高低），另跑"未标记区域逐像素一致性"脚本（关插件 vs 开插件，非光晕区域差值低于阈值）。

### 视觉验收清单
1. 引擎 Bloom 开/关，插件输出逐像素一致（独立性契约）。
2. kernel 半径 0.5 屏时：未标记区域锐度/黑位/对比度与关插件基本一致（不糊场景）。
3. 鸣潮式：核心锐利、近距彩色辉光、Wide 克制不压对比度。
4. 柔和平滑：光晕无色带、无台阶、上采样无块痕。
5. 提亮正确：过阈高光提亮、中间调不动；辉光加性溢出到邻域。
6. 三层半径/染色独立实时生效（范围可控）。
7. 重启编辑器/切关卡/PIE 后状态保持（持久化契约）。
8. UI 真实鼠标 + 多 DPI 验收（沿用 CinematicGlow 的验收纪律）。
9. 固定曝光与自动曝光下均无曝光呼吸（大光晕不引起全画面亮度波动；光晕默认不参与眼适应统计，合成 slot 与豁免在 M2 决策）。
10. TSR / DLSS 开启、相机连续移动下无拖影、闪烁、跳变。
11. 编辑器多视口与预览视口策略生效：主视口应用、材质/Niagara 预览与 SceneCapture 视口跳过。

## 10. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 5.7 RDG/ViewExtension 接口与参考代码（5.6）有差异 | 实现期第一任务先做接口冒烟；CinematicGlow ue57-port 分支可参考 |
| 大 kernel + 高分辨率下 f16 精度色带 | 染色前抖动；验收清单第 4 条盯守 |
| Slate 自绘控件 DPI/窄宽适配工作量 | 控件清单已收敛到 3 个；沿用 CinematicGlow slate-ui skill 经验 |
| unreal-mcp 接入受阻 | HighResShot 兜底路径不依赖 MCP |
| UE 5.7 小版本间渲染接口变动（CinematicGlow 5.7 移植已踩过） | 支持矩阵锁定具体 5.7.x 小版本，升级另行回归 |
| HDR 合成光晕参与眼适应统计导致曝光呼吸 | 合成 slot 与眼适应豁免在 M2 决策，验收清单第 9 条盯守 |
| TSR/上采样器下光晕拖影闪烁 | 验收清单第 10 条盯守；必要时对光晕层单独直方图重投影豁免 |
